# Cemita — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Demo navegable de "Cemita", el lugar único de eventos tech de Puebla: listado, eventos, comunidades, propuesta + moderación, suscripción con vista previa de correo, media kit con imágenes generadas, publicado en Vercel.

**Architecture:** Next.js App Router. Datos de ejemplo en `lib/seed.ts`; lo nuevo (eventos propuestos, cambios de estado, suscripciones) en `localStorage` vía `lib/store.ts`, combinado con el seed. Páginas de UI como client components que leen el store. Imágenes de redes con `next/og` en una ruta que recibe los datos del evento por query string, para que funcione con eventos del seed y con los propuestos.

**Tech Stack:** Next.js (última, App Router) + TypeScript + Tailwind CSS v4, `next/font/google` (Bricolage Grotesque, Inter), Vitest para la lógica pura, Vercel CLI.

**Spec:** `docs/superpowers/specs/2026-11-20-hub-eventos-tech-design.md`

## Global Constraints

- Todo el texto de la UI en español; tono cercano, poblano, con humor, claro.
- Nombre: **Cemita**. Lema: "Todos los eventos tech de Puebla, en una sola cemita."
- Paleta Talavera: cobalto `#1E3A8A`, cobalto oscuro `#14245C`, amarillo `#F5B700`, blanco `#FFFFFF`, crema `#FBF7EE`, tinta `#0F172A`. Definidos una sola vez como tokens (`app/globals.css` `@theme`) y en `lib/brand.ts` para correo e imágenes.
- Tipografía: Bricolage Grotesque (títulos), Inter (texto).
- Mobile-first.
- Zona horaria de presentación: `America/Mexico_City`, locale `es-MX`.
- Comunidades de ejemplo con nombres inventados; aviso visible "Datos de demostración" en el pie.
- Contraseña de moderador: `cemita2026`.
- Todo evento propuesto entra como `pendiente`.
- Publicación: `npx vercel --prod`, URL `*.vercel.app`.

## Review Focus

1. Sin eventos próximos para un filtro → mensaje vacío amable, no lista en blanco. (Task 3)
2. Título largo en post/story → se recorta con elipsis y no se desborda de la imagen. (Task 6)
3. `localStorage` corrupto o inaccesible → se usa el seed sin romper la página. (Task 2)
4. Hora mostrada distinta entre servidor y cliente / zona horaria → siempre formatear en `America/Mexico_City`. (Task 2)
5. Proponer un evento con título repetido o fin antes del inicio → slug único; el formulario rechaza fin < inicio. (Task 2, Task 4)

### Task 2: Modelo de datos, seed y store

**Files:**
- Create: `lib/types.ts`, `lib/seed.ts`, `lib/store.ts`, `lib/format.ts`, `lib/slug.ts`, `lib/useStore.ts`
- Test: `lib/store.test.ts`, `lib/format.test.ts`, `lib/slug.test.ts`

**Interfaces:**
- Produces:
  - `type Community = { slug: string; name: string; description: string; topics: string[]; emoji: string; links: { label: string; url: string }[] }`
  - `type EventStatus = "pendiente" | "aprobado" | "rechazado"`
  - `type TechEvent = { slug: string; title: string; description: string; communitySlug: string; start: string /* ISO con offset -06:00 */; end: string; venue: string; online: boolean; registrationUrl: string; topics: string[]; status: EventStatus; submittedBy: string }`
  - `type Subscription = { email: string; communitySlugs: string[] | "todas"; createdAt: string }`
  - `seedCommunities: Community[]` (6), `seedEvents: TechEvent[]` (11 aprobados entre 2026-11-22 y 2026-12-20 + 1 pendiente para demostrar moderación)
  - `store.ts` (puro, recibe un `Storage`-like): `loadState(storage): State`, `getEvents(state): TechEvent[]`, `addEvent(storage, input: Omit<TechEvent,"slug"|"status">): TechEvent`, `setStatus(storage, slug, status)`, `addSubscription(storage, sub)`, `getSubscriptions(state)`, `subscribersFor(state, communitySlug): Subscription[]`. `State = { added: TechEvent[]; statusOverrides: Record<string, EventStatus>; subscriptions: Subscription[] }` en la clave `cemita:v1`.
  - `upcoming(events, now: Date, communitySlug?: string): TechEvent[]` — aprobados con `end >= now`, ordenados por `start`.
  - `useStore()` hook client: `{ events, communities, subscriptions, addEvent, setStatus, addSubscription }`, re-render tras cambios.
  - `format.ts`: `formatDate(iso): string` (p. ej. "sáb 22 nov"), `formatTime(iso): string` ("18:30"), ambos con `timeZone: "America/Mexico_City"`, `es-MX`.
  - `slugify(title): string`, `uniqueSlug(title, taken: string[]): string`.

- [ ] **Step 1: Tests que fallan**
  - `store.test`: `loadState` con valor `"{basura"` → estado vacío sin lanzar; `getEvents` combina seed + `added` y aplica `statusOverrides`; `addEvent` devuelve `status === "pendiente"`; `setStatus(slug,"aprobado")` hace que aparezca en `upcoming`; `subscribersFor("x")` incluye las de `"todas"` y las que contienen `"x"`; `upcoming` excluye rechazados, pendientes y eventos con `end` < now.
  - `format.test`: `formatTime("2026-11-22T18:30:00-06:00") === "18:30"` aunque `TZ=UTC`.
  - `slug.test`: `slugify("Meetup de IA ¡Puebla!") === "meetup-de-ia-puebla"`; `uniqueSlug("a", ["a","a-2"]) === "a-3"`.
- [ ] **Step 2:** `npm test` → FAIL (módulos no existen).
- [ ] **Step 3:** Implementar los módulos. Seed: comunidades inventadas (p. ej. "Mole & Código", "Angelópolis JS", "Popo Data", "Talavera UX", "Cholula Cloud", "Chiles en Nube"... a criterio), eventos con lugares creíbles de Puebla.
- [ ] **Step 4:** `npm test` → PASS.
- [ ] **Step 5:** Commit `feat: modelo de datos, seed y store local`.
